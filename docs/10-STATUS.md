### F1 발행 — 알아 둘 것

- **예약 큐에 처음 들어오면 `예약, 이렇게 합니다` 슬라이드가 저절로 뜬다**(11장, 2026-08-06 신설).
  새 예약부터 카카오톡 예약 메시지까지 **실제 화면**으로 보여준다. `하루 동안 보지 않기`가 있고,
  닫아도 툴바 `예약 흐름 보기`로 다시 열린다. 원문은 `src/guides/reservation-walkthrough.ts`.
  캡처는 손으로 찍지 말 것 — `npm run build && npx tsx scripts/capture-help-shots.ts` 가
  **테스트 DB의 가짜 예약**으로 22장을 다시 만든다(운영 화면을 찍으면 실명이 커밋된다).

- 카페는 **글쓰기 API 만** 있다. 수정·삭제가 없어 **한번 나간 글은 되돌릴 수 없다**(방어가 두 겹인 이유).
- `code 999`(연속 등록 불가)는 실패가 아니다 — 대기 후 재시도, `retry_count` 증가 없음.
- `publishing` 은 워커 점유 상태. 없으면 같은 글을 다음 워커가 다시 집어 **카페에 중복 게시**된다.
- **봉사가 공지 후 취소되면 예약 큐에서 `봉사 취소 표시`** 를 누른다(2026-07-31 신설). 회차만
  취소로 바뀌어 챗봇·안내에서 빠지고, 카페 글과 발행 기록은 남는다.
- **단톡 공지는 사람이 건다.** 예약 큐의 `카카오톡 공지 예약` 이 문구와 시각(**발행 정시** — 카톡
  예약 메시지가 5분 단위라 +1분은 고를 수 없었다, 2026-08-06 개정)을 주면
  팀장단이 카톡 **예약 메시지**로 등록한다(2026-08-04, 결정 88). 자동 전송 API 는 없다.
  문구에는 **게시판 주소**가 들어간다 — 글 번호는 올라가는 순간 매겨져 미리 알 수 없다.
- `events` enum 은 4단계지만 코드가 실제로 쓰는 값은 `draft`·`canceled` 둘뿐이다.

### F4 챗봇 — 알아 둘 것

- **출처는 어디에도 표시하지 않는다**(2026-07-31, 결정 69). 모델이 본문에 쓰지 못하게 하는 규칙은
  유지(맡기면 지어낸다). `sources` 는 `chat_logs` 에만 남는다.
- 봉사 노출 기준 = **"취소 아님 + 장소 있음"**(결정 24). 발행 여부와 무관하다.
- 툴이 **공지 업로드 시각(`upload`)과 집합 시각(`meetTime`)을 따로** 준다(2026-07-31).
- visibility 필터는 **SQL WHERE 에서 강제**한다(질문자 역할 이하 문서·일정만).
- 임베딩 768차원 강제(3072은 pgvector HNSW 한도 2000 초과).
- **날짜가 있는 것은 문서에 적지 않는다** — `/calendar` 에 넣으면 tool `list_club_schedules` 가
  그때그때 읽는다(2026-08-03, 결정 86). 문서에 남길 것은 회칙·회비·FAQ 처럼 날짜 없는 것뿐이다.
- **답하지 못한 질문은 자동으로 모인다** — `/admin/chatbot` 맨 위 카드 + 주 1회 회장단 메일
  (2026-08-03, 결정 85). 무엇을 채워야 하는지 추측하지 않아도 된다. 질문자는 싣지 않는다.

### F9 모집 — 알아 둘 것

- **면접 불참은 면접관(운영진)이 면접 콘솔에서** 표시한다(2026-07-31, 결정 67). 되돌릴 수 있다.
- **모집 공고 설정은 회장단 전용**(2026-07-31, 결정 66 — 홍보팀 개방을 번복).
- 미채점자가 `received` 로 남아 발표 후 "접수 완료(심사 전)"로 조회되는 것은 **의도된 동작**(결정 40).
- **면접 슬롯을 지우면 배정된 지원자의 배정이 함께 풀린다**(FK set null). 화면이 몇 명인지 경고하고,
  지운 내용은 `audit_logs` 에 `[high]` 로 남는다(2026-08-06, 결정 98).
- 면접관은 **활성 임기의 운영진 이상**만 배정된다(서버 검증). 조 이름 중복도 서버가 409 로 막는다(100·101).
- 지원자 데이터는 기수 단위 hard delete 로만 폐기. 익명 집계만 잔존.

### 캘린더 — 알아 둘 것

- **날짜 있는 것은 캘린더 한 곳에만 둔다.** 문서 화면 머리말에 그렇게 적어 뒀다 — 문서에도 적으면
  한쪽이 낡고, 챗봇은 캘린더를 그때그때 읽으므로 틀린 날짜를 답하게 된다(2026-08-04).
- **`events`(봉사 회차)와 다른 것이다.** events 는 카페 공지 발행 파이프라인(예약·업로드 시각·정원)에
  묶여 있어 총회를 넣으려면 "정원" 같은 칸을 채워야 한다. 봉사는 예약 화면, 그 밖의 일정은 캘린더다.
- **등록·수정·삭제는 회장단**(`schedule.manage`), **조회는 로그인한 전원**(`/calendar` = `requireActor`,
  2026-08-04 결정 89 로 부원에게 개방). 부원에게는 **부원 공개 일정만** 보인다 — 필터는 라우트의
  역할 검사가 아니라 `allowedVisibilities(actor)` 가 건 SQL WHERE 다.
- 도움말 버튼과 "여기 적으면 부원도 바로 봐요" 안내는 **운영진 이상에게만** 보인다(적는 사람에게
  하는 말이다). ~~"챗봇이 부원 질문에 대신 답해요"~~ 는 걷어냈다 — 부원이 직접 보게 된 뒤로는 틀린 말이다.
- 공개 범위는 **문서와 같은 등급**(`member|staff|board`, `src/auth/visibility.ts` 공용).
- 시간·장소가 미정이어도 등록된다. 비워 두면 챗봇이 "아직 안 정해졌다"고 답한다.

|---|---|
| **카카오톡 공지 예약 버튼** | 카페에 올라간 뒤 단톡방 공지는 팀장단이 매번 처음부터 썼다. 보내는 건 여전히 사람이지만(자동 전송 API 없음) **문구와 시각은 시스템이 준다**(결정 88) |
| 메뉴 `일정` → **`캘린더`**, 문서 화면에 "일정은 캘린더에만" 안내 | 담는 곳(캘린더)과 담기는 것(일정)이 같은 이름이라 어디에 적어야 하는지가 흐릿했다. 이름을 갈라 놓고, 문서에 날짜를 또 적지 않도록 그 화면에서 막는다 |
| **캘린더를 부원에게도 연다** | 쓰기는 이미 회장단으로 잠겨 있고 보이는 범위는 SQL 필터가 가른다 — 화면을 열어도 새로 열리는 것이 없다. 챗봇은 물어본 것에, 달력은 훑어보는 것에 답한다(결정 89) |
| **로그인 첫 화면 = 로그인·가입 갈림길** | 가입할 사람이 로그인 화면에 이메일을 넣고 **오지 않을 코드를 기다렸다**. 입력칸이 먼저 보이면 그 아래 안내는 읽히지 않는다(결정 84) |
| **답하지 못한 질문 리포트** | 무엇을 문서로 채워야 하는지가 `chat_logs` 에 매일 쌓이기만 하고 아무도 읽지 않았다. 콘솔 카드 + 주 1회 메일 두 경로로 **사람을 찾아가게** 했다(85) |
| **동아리 일정 캘린더 + 챗봇 tool** | 총회·MT 를 문서에 적으면 학기마다 썩는다. `/calendar` 에 넣으면 챗봇이 지금 값을 읽는다 — **고쳐야 할 문서를 없앤 것**(86) |
| 홈·상단 메뉴 순서 | 손이 자주 가는 순서(예약·템플릿)와 화면 순서가 어긋나 있었다. 홈 카드와 상단 메뉴를 같은 순서로 맞췄다 |
