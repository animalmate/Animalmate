# 09. 프로젝트 현황 스냅샷 (2026-07-29 갱신)

> **목적**: 코드를 읽지 않은 외부 기술 조언자에게 현재 구현 상태를 있는 그대로 전달한다.
> **작성 방법**: 실제 코드·마이그레이션·설정 파일을 확인해서 썼다. 기획 문서(01~08)가 말하는 것과
> 코드가 하는 것이 다르면 **⚠ 문서와 불일치**로 표기했다. 계획이 아니라 현재 코드 기준이다.
> **한계**: Vercel/Supabase 운영 콘솔은 확인할 수 없다. 배포·크론 등록 상태는 문서 기록과
> 코드 존재 여부로만 판단했고, 그 사실을 각 항목에 명시했다.

## 1. 한 페이지 요약

한 줄 정의: 300명 규모 대학생 봉사 동아리의 운영 자동화 웹서비스. 네이버 카페는 아카이브로 두고
그 위에 **공지 발행 루프**, **RAG 챗봇**, **신입 모집 전 과정**을 얹었다.

| 분류 | 항목 |
|---|---|
| **① 배포되어 실사용 가능** | 인증(가입코드+이메일 OTP), 권한·감사로그, 조직 관리(회원·역할·팀·팀장단), 회원 탈퇴, 게시판 레지스트리, 가입코드 관리, **F1 공지 발행 루프**(예약→미완성 점검→카페 실게시), **F9 신입 모집 전 과정**(공고·공개 지원서·CSV 업로드·서류 채점·확정·면접 배정·면접 콘솔·최종 결정·비로그인 조회·데이터 폐기·면접 당일 도구), **개인정보처리방침(`/privacy`)+가입·지원서 동의**, 헬스체크 |

| **③ 미구현** | **F8 총무 모듈**(dues/expenses) — 테이블도 라우트도 화면도 0. 설계만 03-DATA-MODEL §118에 확정. **무기한 연기(2026-07-28 결정)** — 요청 전 착수 금지 |

**한 줄 판단**: F1·F9·인증·조직관리는 완성되어 실제로 돌릴 수 있는 상태. F4 챗봇은 그릇만 있고
내용물이 비어 있다. F8은 착수 전. 파일럿의 실질적 병목은 **챗봇 문서 입력**과 **운영 검증**이다.

**성능(2026-07-29 측정·수정)**: "좀 느리다"의 주범은 코드가 아니라 배치였다 — 함수가 버지니아
(`iad1`)에서 돌고 DB 는 서울이라 쿼리 1회당 태평양 왕복 ≈ 180ms. 리전을 서울(`icn1`)로 고정하고,
인증 조회 3왕복 → 1왕복, 폰트 CSS `@import` 워터폴 제거, 모든 페이지가 받던 이미지 302KB → 28KB.
근거와 되돌리면 안 되는 이유는 07-DECISIONS 50~53 / README「성능에서 지켜야 할 것」.
**아직 배포 전이다** — 리전 변경은 배포돼야 적용된다(확인법은 README).

## 2. 기능 현황

### F1 — 공지 발행 (완성, 실카페 게시 중)

**실제 동작 플로우**

1. 운영진이 `/reservations/new`에서 예약을 만든다. 양식(`post_templates`)을 고르면 기본 장소·정원·
   집합시간·업로드 시각이 자동으로 채워져, 실제로 고르는 건 **봉사 일자와 업로드 날짜뿐**이다.
   여러 회차를 일정 행으로 추가할 수 있고 회차마다 미리보기 팝업이 있다.
2. 저장하면 `scheduled_posts`(글) + `events`(회차)가 함께 생기고, 필수값(일시/장소/정원)과
   미치환 플레이스홀더 유무로 **상태가 자동 판정**된다(결정 26 — 수동 '완성 처리' 버튼은 제거됨).
3. 매일 도는 크론이 발행 D-3, D-1에 미완성(`draft`) 예약을 찾아 팀장단에게 메일을 보낸다.
   D-1은 "내일 발행 보류 예정"으로 격상. 중복 발송은 `notice_check_log`가 막는다.
4. 매분 도는 발행 워커가 `scheduled` 이면서 시각이 된 글을 최대 5건 집어 간다(`publishing`으로
   점유 → 중복 발행 방지). 게시 직전 **게시판 쓰기 권한을 다시 확인**하고, `{{장소}}{{정원}}`을
   `events` 값으로 최종 치환한다. 미치환 키가 남으면 게시하지 않고 즉시 `failed`.
5. 네이버 카페 글쓰기 API 호출. 성공하면 글 URL 저장. **code 999(연속 등록 불가)는 실패가 아니라**
   대기 후 재시도(retry_count 증가 없음). 그 외 오류는 재시도 2회까지, 넘으면 `failed` + 회장단 메일.

**최초 설계에서 달라진 점**

- **"매월 N번째 X요일" 반복 규칙 일괄 생성 폐기**(2026-07-24). 정기 봉사가 그렇게 고정되는 경우가
  드물어 쓰이지 않았다. `src/recurrence/` 전체와 화면·API를 삭제했고, 남아 있던 `recurring_rules`
  테이블도 **0행 확인 후 삭제했다**(마이그레이션 0020, 2026-07-28). `events.rule_id` 컬럼도 함께.
- **크론 자동 회차 생성 → 일일 유지보수로 전환**. `/api/cron/draft-generate` 라우트 이름은
  pg_cron 잡 호환을 위해 유지하고 있어 **이름과 하는 일이 다르다**(README pg_cron SQL에 실동작 병기).
  지금 하는 일 = ① 미완성 점검 ② 임기 만료 강등 ③ 레이트리밋 정리.
- **발행 직전 치환 도입**(결정 24 계열, 마이그레이션 0007). 본문에 플레이스홀더를 남겨 두고
  게시 직전 `events` 값으로 바꾼다 — 회차별 수정이 그대로 반영된다.
- **발행 지연 최적화**(결정 25): 15초 버퍼 제거, 단건 발행은 대기 없음, 직전 호출이 30초 이내일 때만
  잔여 시간만 대기.

### F4 — RAG 챗봇 (코드 완성 / 내용물 없음)

**실제 동작 플로우**

1. 로그인 사용자가 `/chatbot`에서 질문한다(비로그인 접근 불가, `requireActor`).
2. 쿼터 확인 — 인당 일 30회, 전역 분기 6000회(기본값, `app_settings`로 회장단이 조정). 킬스위치 있음.
3. 질문을 임베딩(`gemini-embedding-2`, **768차원 강제** — 3072는 pgvector HNSW 한도 2000 초과)하고
   `doc_chunks`를 코사인 근접 검색. **visibility 필터는 SQL WHERE에서 강제**한다(질문자 역할 이하 문서만).
4. 검색 결과 + 질문을 **데이터로**, 시스템 지시는 `systemInstruction`으로 **분리**해서 Gemini에 전달
   (프롬프트 인젝션 방어). 모델이 필요하면 봉사 일정 tool 2개를 호출한다.
5. 근거가 없으면 지어내지 않고 고정 문구로 핸드오프. 개인정보 요청은 별도 거절. 답변은 안전 마크다운
   렌더(원시 HTML 금지) + CSP nonce.
6. 질문·답변·출처·핸드오프 여부를 `chat_logs`에 기록.

**최초 설계에서 달라진 점**

- **출처는 모델이 아니라 UI가 표시한다**(2026-07-28 정리, 07-DECISIONS 46). CLAUDE.md #7은 원래
  "답변에 출처 문서명을 표시한다"였는데 시스템 프롬프트에는 정반대 규칙이 들어가 있었다.
  → 시스템 프롬프트는 그대로 두고(본문에 출처 금지), **검색 메타데이터(`sources`)로 답변 아래에
  출처 칩을 렌더링**한다. 모델에게 맡기면 없는 문서명을 지어낼 수 있지만, 검색이 실제로 집어 온
  목록은 지어낼 수 없다. 핸드오프한 답변에는 칩을 붙이지 않는다. CLAUDE.md #7도 이 방식으로 개정.
- **코사인 컷오프로 관련도를 자르지 않는다 — 모델이 판단**(결정 22). 짧은 한국어 질문은 유사도가
  낮게 나와 컷오프가 정답을 버렸다.
- **봉사 노출 기준 완화**(결정 20 → 24): "발행된 회차만"에서 "취소 아님 + 장소 정해짐"으로. 발행(카페
  업로드)과 챗봇 안내는 별개 관심사라는 판단.
- 문서 업로드는 `.md`/`.txt`만(결정 18). docx/PDF 파싱 없음.

### F8 — 총무 (미구현)

- **테이블 0, 라우트 0, 화면 0.** `dues`·`expenses`는 03-DATA-MODEL §118에 스키마만 확정되어 있다.
- 설계 확정 사항: 접근은 **총무 + 회장단만**(일반 운영진 불가). dues는 학기 단위 납부 상태만 두고
  **금액·계좌는 저장하지 않는다**. expenses는 승인 플로우 없는 기록 대장, 영수증은 비공개 Storage.
- 권한 모델상 걸림돌: 현재 `Action` 타입에 총무용 액션이 없고, `board_position='treasurer'`를
  권한 판단에 쓰는 코드가 없다. **"총무만" 권한을 구현하려면 `authorize()` 확장이 필요하다.**

### F9 — 신입 모집 (완성, 가장 최근까지 손댄 영역)

**실제 동작 플로우**

1. **공고 설정**(`/admin/recruit/notice-edit`, 운영진 진입 가능·필드 단위 권한) — 공고 본문·포스터
   이미지(Supabase Storage)·지원서 문항 문구·면접 장소 프리셋·대기실 업무 이름. 마감 스위치와
   합격자 안내문은 회장단만(결정 31).
2. **공개 접수** — `/recruit/notice`(공고), `/recruit/apply`(지원서 폼, 비로그인). 제출은 10분 5회
   레이트리밋, 이름+전화 중복 시 409.
3. **CSV 업로드**(`/admin/recruit/upload`, 회장단) — 열↔필드 매핑, 매핑 프리셋 저장, 미리보기, 중복 감지.
4. **서류 채점**(`/admin/recruit/screening`, 운영진) — 목록↔우패널, 타인 점수 표시, 0~10점 0.5단위.
5. **집계·서류 확정**(`/admin/recruit/tally`, 회장단) — 평균 내림차순, 상위 N 선택, 일괄 확정.
   일괄 상태 변경은 **서버가 기수 범위를 강제**하고 제외 사유를 나눠 돌려준다(결정 29).
6. **면접 배정**(`/admin/recruit/interview/assign`, 회장단) — 슬롯 격자, 면접관 배정, 비대면 희망 표시,
   **면접 시간표 한 장 보기**(엑셀 모양 표) + **대기실 업무 배정표**(마이그레이션 0019). 둘 다 탭 구분
   복사로 엑셀·카톡에 붙는다.
7. **면접 콘솔**(`/admin/recruit/interview/console`, 운영진) — 슬롯(조)별 묶음, '지금' 시간대 강조,
   개인 메모 자동 저장(디바운스 + 순서 역전 방어), 점수 기본값 없음(결정 28).
8. **최종 결정**(`/admin/recruit/final`, 회장단) — 면접 기록 없음 경고, noshow 표시, 공개 스위치 2개
   (면접 일정 / 최종 결과, 2단계 확인).
9. **비로그인 조회**(`/recruit`) — 이름+전화 정확 일치, noindex, IP 분당 5회 + 실패 10회 시 1시간 차단,
   **시도 입력값은 저장하지 않는다**.
10. **데이터 폐기** — 기수 단위 hard delete. 인적사항·자기소개서·메모·점수 전량 삭제, 익명 집계만 잔존.

### 인증 (완성)

- **가입**: 학기별 가입코드(활성 코드 항상 1개, 부분 유니크 인덱스로 DB가 강제) + 이메일 6자리 OTP.

- **로그인**: 이메일 OTP만. 비밀번호 없음.
- **세션**: 커스텀 HS256 JWT 쿠키(httpOnly, sameSite=lax). 세션 테이블 없이 `users.session_version`으로
  무효화 — 값을 1 올리면 그 계정의 모든 기기 세션이 즉시 끊긴다(결정 11). 비활성화·강등 시 자동 증가(결정 13).
- **계정 열거 차단**(결정 9): 가입 요청 응답은 가입 여부와 무관하게 동일하고, "이미 가입됨"은
  본인 메일함으로만 전달된다.
- **레이트리밋**: DB 기반 고정 윈도(서버리스라 메모리 카운터가 무력). 가입/로그인 요청 시간당 10회,
  OTP 검증 20회, **수신 주소 기준** 발송 5회(메일 폭탄 방어).
- 권한 판단은 순수 함수 `authorize()` 한 곳. 모든 쓰기는 `membership active` → 역할 → 소유권 순서로
  검사하고, 회장단·시스템관리자의 소유권 우회는 audit에 `override`로 남는다.

### 조직 관리 (완성)

- **탈퇴**(결정 30): 행 삭제가 아니라 **개인정보 삭제 + 영구 잠금**. FK와 audit 무결성 때문. 작성물은
  남고 작성자만 '탈퇴한 회원'이 된다. 같은 이메일로 재가입 가능(별개의 새 계정).

  멤버십을 `expired`로 바꾸고 `users.session_version`을 올려 **그 계정의 모든 기기 세션을 즉시 끊는다**.

  (`term_end === 오늘`은 만료 아님 — "8/31까지"라고 했으면 그날은 쓸 수 있어야 한다).
  - 이전 상태: **문서 3곳이 "크론이 매일 강등한다"고 적고 있었지만 그런 코드가 없었다.**

  - **아직 실전 검증 전**: 실제로 임기가 지난 계정이 생겼을 때 크론 로그·audit을 확인해야 한다.

**핵심 상태머신 (현재 코드 기준)**

*발행 (`post_status`)*
```
draft ──→ ready ──→ scheduled ──→ publishing ──→ published
  ↑         │           │  ↑           │
  └─────────┘           │  └───────────┤(code 999 대기 / 재시도 여유)
                        └──→ failed ←──┘(재시도 2회 초과)
failed ──→ scheduled | draft   (운영진이 재시도 큐로 되돌림)
```
- `publishing`은 워커 점유 상태. 이게 없으면 한 사이클이 건당 30초라 다음 워커가 같은 글을 다시 집어
  **카페에 중복 게시**된다(삭제 API가 없어 복구 불가).
- code 999는 실패가 아니다 — `scheduled` 유지, `retry_count` 증가 없음.

*모집 (`recruit_status`)*
```
received ──→ doc_pass ──→ interview_done ──→ final_pass | final_fail
   │             │    ↑         │
   │             │    └─────────┘  (면접 점수 1개 이상 저장 시 자동 전이 /
   │             │                  0개로 감소 시 자동 복귀)
   │             └──→ interview_noshow ──→ final_pass | final_fail
   └──→ doc_fail
```
- `received → received`, `→ interview_done` 수동 지정 경로는 **없다**(면접 완료는 점수 존재라는
  사실의 반영이라 자동 전이로만 결정).
- 서버가 `canTransition()`으로 전이를 검사한다. 이 가드는 한때 정의만 있고 호출되지 않아,
  심사도 면접도 안 거친 지원자가 최종 합격이 될 수 있었다(수정 완료).

*회차 (`event_status`)* — `draft → published → done | canceled`로 **설계**되었으나, 코드는
`draft`(생성)와 `canceled`(예약 취소)만 쓴다.

*멤버십 (`membership_status`)* — `active → expired`. 전이 경로 3개: **임기 만료(자동, 일일 크론)** /
비활성화(수동, 복구 가능) / 탈퇴(되돌릴 수 없음 + 개인정보 삭제).

**즉시 해야 하는 것 (2026-07-29 기준)**

1. **마이그레이션 0020을 실 DB에 적용.** 아직 적용 전이다. **코드 배포 먼저, `npm run db:migrate` 나중**
   — 컬럼을 지우는 마이그레이션이라 순서가 평소와 반대다(옛 코드가 `events.rule_id`를 SELECT한다).

   실패 / 실패 원인이 EPIPE 스택에 가려짐). 전부 수정. **RLS는 덤프에 들어 있다** — public 29개
   테이블 전부에 `ENABLE ROW LEVEL SECURITY`, `CREATE POLICY` 0개. 복원 후에도 29/29 켜짐 확인.
   상세는 05-ASSET-REGISTRY「실행 기록」.
3. **`BACKUP_ENCRYPTION_KEY` 로테이션.** 이 키가 2026-07-28 작업 중 평문으로 노출됐다. 키 하나로
   지원자 PII가 든 **모든 백업이 열린다.** 2026-07-29 확인 시점에 Actions 시크릿의 `updated_at`이
   여전히 최초 생성 시각(`2026-07-28T05:04:07Z`)이라 **아직 교체되지 않았다.**

     키인지"를 함께 적을 것.

   회비·봉사시간 인정·연락처 5건). **현재 파일럿의 가장 큰 병목이다.**
