### F1 발행 — 알아 둘 것

- **예약 큐에 처음 들어오면 `예약, 이렇게 합니다` 슬라이드가 저절로 뜬다**(11장, 2026-08-06 신설).
  새 예약부터 카카오톡 예약 메시지까지 **실제 화면**으로 보여준다. `하루 동안 보지 않기`가 있고,
  닫아도 툴바 `예약 흐름 보기`로 다시 열린다. 원문은 `src/guides/reservation-walkthrough.ts`.
  캡처는 손으로 찍지 말 것 — `npm run build && npx tsx scripts/capture-help-shots.ts` 가
  **테스트 DB의 가짜 예약**으로 22장을 다시 만든다(운영 화면을 찍으면 실명이 커밋된다).

- 카페는 **글쓰기 API 만** 있다. 수정·삭제가 없어 **한번 나간 글은 되돌릴 수 없다**(방어가 두 겹인 이유).
- `code 999`(연속 등록 불가)는 실패가 아니다 — 대기 후 재시도, `retry_count` 증가 없음.
- `publishing` 은 워커 점유 상태. 없으면 같은 글을 다음 워커가 다시 집어 **카페에 중복 게시**된다.
- **봉사가 공지 후 취소되면 예약 큐에서 `봉사 취소 표시`** 를 누른다(2026-07-31 신설). 회차만
  취소로 바뀌어 챗봇·안내에서 빠지고, 카페 글과 발행 기록은 남는다.
- **단톡 공지는 사람이 건다.** 예약 큐의 `카카오톡 공지 예약` 이 문구와 시각(**발행 정시** — 카톡
  예약 메시지가 5분 단위라 +1분은 고를 수 없었다, 2026-08-06 개정)을 주면
  팀장단이 카톡 **예약 메시지**로 등록한다(2026-08-04, 결정 88). 자동 전송 API 는 없다.
  문구에는 **게시판 주소**가 들어간다 — 글 번호는 올라가는 순간 매겨져 미리 알 수 없다.
- `events` enum 은 4단계지만 코드가 실제로 쓰는 값은 `draft`·`canceled` 둘뿐이다.

### F4 챗봇 — 알아 둘 것

- **출처는 어디에도 표시하지 않는다**(2026-07-31, 결정 69). 모델이 본문에 쓰지 못하게 하는 규칙은
  유지(맡기면 지어낸다). `sources` 는 `chat_logs` 에만 남는다.
- 봉사 노출 기준 = **"취소 아님 + 장소 있음"**(결정 24). 발행 여부와 무관하다.
- 툴이 **공지 업로드 시각(`upload`)과 집합 시각(`meetTime`)을 따로** 준다(2026-07-31).
- visibility 필터는 **SQL WHERE 에서 강제**한다(질문자 역할 이하 문서·일정만).
- 임베딩 768차원 강제(3072은 pgvector HNSW 한도 2000 초과).
- **날짜가 있는 것은 문서에 적지 않는다** — `/calendar` 에 넣으면 tool `list_club_schedules` 가
  그때그때 읽는다(2026-08-03, 결정 86). 문서에 남길 것은 회칙·회비·FAQ 처럼 날짜 없는 것뿐이다.
- **답하지 못한 질문은 자동으로 모인다** — `/admin/chatbot` 맨 위 카드 + 주 1회 회장단 메일
  (2026-08-03, 결정 85). 무엇을 채워야 하는지 추측하지 않아도 된다. 질문자는 싣지 않는다.
- **봉사 회차가 0건일 때 "없어요"로 끝내지 않는다**(2026-08-24, 결정 139). 회차 → **팀 가이드북의
  평소 운영 방식** → **기본 안내 문구** 3단으로 내려간다. 기본 문구는 `/admin/chatbot` 에서 회장단이 고친다.
  - 회차가 **있을 때는** 이 안내를 붙이지 않는다(비대칭). 붙이면 정확한 답까지 의심스러워진다.
  - 프롬프트가 **확정 일정과 평소 방식을 섞지 못하게** 막는다 — "보통 토요일"을 "이번 주 토요일"로
    말하면 부원이 헛걸음한다.
  - ⚠ `toolGrounded()` 를 `count > 0` 로 되돌리지 말 것. 그러면 회차 0건이 곧바로 핸드오프로 덮여
    **폴백이 통째로 죽는다**(`src/rag/fallback.test.ts` 가 잡는다).

### F9 모집 — 알아 둘 것

- **면접 불참은 면접관(운영진)이 면접 콘솔에서** 표시한다(2026-07-31, 결정 67). 되돌릴 수 있다.
- **모집 공고 편집은 회장단 + `teams.can_edit_notice` 가 켜진 팀**(2026-08-25, 결정 140 — 결정 66 을
  제대로 다시 열었다). 회장단이 **회원 → 팀 관리 → 공고 편집 권한 주기**로 팀 단위로 켠다.
  플래그를 켜기 전까지는 회장단 전용과 동작이 같다(전 팀 기본 false).
  **플래그를 켜면 0번 화면 전부 + 지원자 공개 스위치까지 그 팀이 쓴다**(2026-08-25, 결정 141로 확대).
  켜도 회장단만 하는 것: **기수 삭제**, 그리고 합격 여부를 정하는 행위 — 서류/최종 확정·면접 배정·
  지원자 팀 변경·자료 폐기·CSV export. 경계는 "대외에 나가느냐"가 아니라 **"합격을 정하느냐"**다.
  ⚠ `resultPublic`(최종 결과 공개)이 이 권한에서 가장 무겁다 — 켜면 지원자가 즉시 보고 되돌릴 수 없다.
  ⚠ **팀 이름으로 홍보팀을 알아내는 코드를 다시 만들지 말 것** — 그렇게 만든 `isPRTeamOrPrivileged` 는
  UUID 를 이름처럼 비교해 **항상 false** 였다(결정 66).
- 미채점자가 `received` 로 남아 발표 후 "접수 완료(심사 전)"로 조회되는 것은 **의도된 동작**(결정 40).
- **면접 슬롯을 지우면 배정된 지원자의 배정이 함께 풀린다**(FK set null). 화면이 몇 명인지 경고하고,
  지운 내용은 `audit_logs` 에 `[high]` 로 남는다(2026-08-06, 결정 98).
- 면접관은 **활성 임기의 운영진 이상**만 배정된다(서버 검증). 조 이름 중복도 서버가 409 로 막는다(100·101).
- **지원자가 들어오는 길은 사이트 지원 폼 하나뿐이다.** CSV 업로드 화면은 **폐기했다**
  (2026-08-21, 결정 123). 33기는 구글 폼 응답 CSV 로 받았고 그 경로에 붙어 있던 값 보정
  (전화번호 앞 0·생년월일 표기·CP949·중복쌍·주소 경고, 결정 113~117·120~121)은 **시트를 거쳐서**
  필요했던 것이다. 폼은 서버가 저장 전에 값을 검증한다.
  ⚠ **지원자를 손으로 한 명 추가할 방법은 없다** — 예외가 생기면 마감 스위치를 잠시 꺼서 본인이 넣게 한다.
- **채점을 저장할 때 명단을 다시 받지 않는다**(2026-08-20, 결정 119). 203명 기준 저장 1회가
  844KB → 66KB, 167ms 다. 첫 로드는 여전히 전문 포함 582KB 를 한 번 받는다(운영 실측).
- **면접 배정 화면은 1·2·3 세 단계짜리 한 장이다**(2026-08-21, 결정 124). 옛 슬롯 카드 42장
  목록은 걷어냈다 — 배정 보드와 같은 것을 두 번 그리고 있었다. 슬롯 삭제는 보드의 시간 칸에 있다.
- **최종 결정 대상은 면접에 배정된 사람만이다**(2026-08-21, 결정 125). 서류 탈락·미배정·
  불참은 표에 없고, 표 위에 **숫자로** 뜬다.
- **면접 콘솔은 시간대를 고르기 전에는 비어 있다**(2026-08-21, 결정 128). 왼쪽이 `1 시간대 고르기`
  / `2 지원자 고르기` 두 상자로 나뉘고, 전원을 보려면 `전체 보기`를 누른다. **팀 필터는 없앴다.**
- **면접 콘솔 오른쪽 순서** = 자기소개 · 가치관 및 계기 · **대외활동 / 알바 경험** · 서류 채점 기록 ·
  내 메모(결정 129). 대외활동은 비어 있어도 칸이 남는다.
- **상단 사실 줄은 값 길이에 맞춰 칸을 나눈다**(2026-08-21, 결정 132). 예전에는 다섯 칸을 똑같이
  나누고 한 줄로 잘라서 **학교·학과가 203명 중 104명 잘려 있었다**(넓은 화면에서도 똑같았다 —
  본문이 max-width 로 묶여 있다). 지금은 학교·학과가 4/12칸 + 최대 4줄이라 실측 최대 54자도 다 보인다.
- **면접 콘솔과 최종 결정 사이에 5번 최종 검토 화면(`/recruit/review`)이 있다**(2026-08-23,
  결정 133). 운영진 전원이 보는 화면으로, 면접 본 사람을 팀별로 묶어 면접 점수·지망 팀·면접
  총평을 함께 본다. 최종 결정은 5번 → **6번**으로 밀렸다.
- **최종 검토에서 팀장단이 탈락/다른 팀을 체크해 의견을 남긴다**(2026-08-24, 결정 136). 서류
  점수는 뺐다(2번 화면에 있다). 표시는 **의견이지 결정이 아니다** — 상태·배정 팀을 건드리지
  않고, 합격 여부는 여전히 6번에서 회장단이 정한다.
- **'다른 팀' 표시에 갈 팀을 골라 두면, 그 팀 박스 맨 위에도 다른 색 칸으로 뜬다**(2026-08-24,
  결정 137). "5팀 → 4팀"처럼 원래 팀을 함께 적어, 자기 팀 화면만 보는 팀장도 밖에서 넘어오는
  사람을 놓치지 않는다. 이 칸은 **알림 전용**이라 탈락/다른 팀 체크나 갈 팀 변경이 안 된다 —
  둘 다 그 사람의 원래 팀 박스에서만 한다. 박스 제목 인원수에도 더해진다("11명 (8 + 3)").
  같은 화면에 **전화번호** 칸도 추가했다.
- **6번 최종 결정은 5번 표시를 그대로 확정한다**(2026-08-24, 결정 138). 회장단이 체크박스로
  합격자를 다시 고르던 매트릭스를 걷어냈다 — `drop` → 불합격 / `move` + 갈 팀 → 합격(최종 팀은
  그 팀) / 표시 없음 → 합격으로 계산한 **결과 미리보기 표**와 확정 버튼 하나다. 저장 순서는
  **팀 먼저, 상태 나중**이고 팀 배정이 실패하면 상태는 하나도 안 바꾼다.
  ⚠ **확정을 막는 두 가지**: '다른 팀'인데 갈 팀을 안 고른 **팀 미정**(회장단이 대신 정하면 안
  된다) · 표시도 점수도 없는 **면접 채점 미기록**(자동 합격에서 뺀다). 둘 다 이름까지 적어 준다.
  **권한 경계는 그대로다** — 저장하는 것은 여전히 회장단이고, 바뀐 것은 명단을 손으로 다시
  만들던 입력 방식이다.
- ⚠ **생년월일은 등록 후 어느 화면에서도 못 고친다.** 지원자 수정 API 가 받는 것은
  `status·slotId·interviewLink·nearStation·assignedTeam` 뿐이다.
- 지원자 데이터는 기수 단위 hard delete 로만 폐기. 익명 집계만 잔존.

### 캘린더 — 알아 둘 것

- **날짜 있는 것은 캘린더 한 곳에만 둔다.** 문서 화면 머리말에 그렇게 적어 뒀다 — 문서에도 적으면
  한쪽이 낡고, 챗봇은 캘린더를 그때그때 읽으므로 틀린 날짜를 답하게 된다(2026-08-04).
- **`events`(봉사 회차)와 다른 것이다.** events 는 카페 공지 발행 파이프라인(예약·업로드 시각·정원)에
  묶여 있어 총회를 넣으려면 "정원" 같은 칸을 채워야 한다. 봉사는 예약 화면, 그 밖의 일정은 캘린더다.
- **등록·수정·삭제는 회장단**(`schedule.manage`), **조회는 로그인한 전원**(`/calendar` = `requireActor`,
  2026-08-04 결정 89 로 부원에게 개방). 부원에게는 **부원 공개 일정만** 보인다 — 필터는 라우트의
  역할 검사가 아니라 `allowedVisibilities(actor)` 가 건 SQL WHERE 다.
- 도움말 버튼과 "여기 적으면 부원도 바로 봐요" 안내는 **운영진 이상에게만** 보인다(적는 사람에게
  하는 말이다). "챗봇이 부원 질문에 대신 답해요"라는 문구는 걷어냈다 — 부원이 직접 보게 된 뒤로는 틀린 말이다.
- 공개 범위는 **문서와 같은 등급**(`member|staff|board`, `src/auth/visibility.ts` 공용).
- 시간·장소가 미정이어도 등록된다. 비워 두면 챗봇이 "아직 안 정해졌다"고 답한다.

### 팀 가이드북 — 알아 둘 것

- **PDF 만 받는다.** PPTX 는 브라우저가 못 연다 — "눌러서 바로 보기"가 다운로드가 된다.
  파워포인트에서 PDF 로 저장해 올린다. 상한 20MB.
- **올리는 사람 = 그 팀 팀장단 + 회장단**(`guidebook.manage`). 팀원은 보기만 된다. **보기는 부원 포함 전원.**
- **파일과 챗봇 본문은 별개다.** 추출이 실패해도 파일 보기는 된다(딱지가 `챗봇 미반영`).
- **챗봇에 들어가는 것은 가이드북 전문이 아니라 봉사 운영 정보 요약**이다(여는 요일·주기, 신청 방법,
  공지 방식, 준비물). 요약에 없는 것을 물으면 챗봇이 `/guidebooks` 링크로 안내한다.
- **`내용 확인`에서 저장을 눌러야 챗봇이 읽는다.** 안 누르면 `확인 대기`로 남는다 — 파일만 올라간 상태다.
- 글자를 못 찾았어도(이미지 슬라이드) **검수 상자에 직접 적어 넣으면** 챗봇이 답한다.
- 업로드는 **브라우저 → Storage 직접**(Vercel 본문 상한 4.5MB 회피). 버킷은 **비공개**,
  보기는 30분짜리 서명 URL 을 화면 열 때마다 새로 발급한다.
- ⚠ **Supabase 에 비공개 버킷 `team-guidebooks` 가 있어야 한다.** 없으면 업로드가 서명 URL 발급에서 실패한다.

## 6. 최근에 바뀐 것 (2026-08-24)

| 무엇 | 왜 |
|---|---|
| **최종 검토 화면 신설(`/recruit/review`)** | 면접 콘솔과 최종 결정 사이에 운영진 전원이 보는 화면을 넣었다. 면접 본 사람을 팀별로 묶어 면접 점수·지망 팀·면접 총평을 함께 본다. 최종 결정은 5번 → 6번으로 밀렸다(133) |
| **최종 검토에 탈락/다른 팀 표시, 서류 점수는 뺐다** | 예전에는 완전한 읽기 전용이라 팀장단이 회의에서 낸 의견이 남는 자리가 없었다. 표시는 **의견이지 결정이 아니다** — 상태·배정 팀을 안 건드리고, 합격 여부는 여전히 6번에서 회장단이 정한다. 서류 이야기는 2번에서 끝났으므로 뺐다(136) |
| **'다른 팀' 표시를 갈 팀 박스에도 보이게, 전화번호 칸 추가** | 표시는 지원자의 **원래 팀** 박스에서 거는데, 정작 그 사람이 갈 팀장은 자기 팀 화면만 봐서는 넘어오는 사람을 알 방법이 없었다. 갈 팀 박스 맨 위에 "5팀 → 4팀" 처럼 원래 팀을 적은 알림 칸(다른 색, 체크 불가)을 얹고 인원수에도 더했다("11명 (8 + 3)"). 회의 중 바로 연락할 일이 있어 전화번호도 함께 보이게 했다(137) |
| **6번 최종 결정 = 5번 표시 그대로 확정** | 5번이 생긴 뒤로 팀장단 회의가 결론을 내는데, 6번은 그대로 남아 회장단이 체크박스로 명단을 처음부터 다시 만들고 있었다 — 같은 결론을 두 번 만드는 셈이고 두 화면이 갈릴 자리였다. 매트릭스를 걷어내고 표시로 계산한 **결과 미리보기 + 확정 버튼 하나**로 바꿨다. 팀 미정·면접 채점 미기록은 확정을 막고 이름까지 알린다. 저장하는 권한은 그대로 회장단이다(138) |
| **면접 불참 되돌리기가 점수 가진 사람을 서류 합격으로 떨어뜨리던 버그** | 되돌린 도착지를 `noshow` 불리언으로 고정했었다 — 점수가 있어도 "면접을 안 봤다"로 해석해 최종 확정에서 조용히 빠졌다. 도착지를 면접 점수 개수에서 계산하도록 고쳤다(134) |
| **최종 검토 펼치기 버튼 · 폰 카드 개선** | 파란 글씨 '펼치기'가 링크로 읽혀 총평이 접힌 채 지나쳐졌다 — 테두리·화살표·펼친 색을 준 버튼으로 바꿨다. 폰 카드는 학교·학과·서류 점수를 빼고 면접 점수 하나를 크게 세웠다(135) |
