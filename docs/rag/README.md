# RAG 문서 원문 (챗봇 지식베이스에 넣을 마크다운)

이 폴더의 `.md` 는 **개발 문서가 아니라 챗봇이 읽을 안내 문서의 원문**이다.
`/documents` 화면에 붙여넣어야 실제로 챗봇이 읽는다 — 이 파일이 리포에 있는 것만으로는 아무 일도 일어나지 않는다.

## 넣는 법

1. 회장단 계정으로 `/documents` 를 연다.
2. 새 문서를 만들고 **제목**과 **공개 범위**를 아래 표대로 지정한다.
3. 파일 내용을 통째로 붙여넣고 저장한다(첫 줄 `# 제목` 은 빼도 되고 넣어도 된다 — 검색 문맥에 도움이 된다).
4. 저장하면 자동으로 청킹·임베딩된다. 따로 할 일은 없다.

**또는 스크립트로 한 번에 올린다**(손으로 붙여넣다 공개 범위를 잘못 고르는 사고를 막는다):

```bash
npx tsx --conditions=react-server scripts/sync-rag-docs.ts --actor <회장단 userId>          # 미리보기
npx tsx --conditions=react-server scripts/sync-rag-docs.ts --actor <회장단 userId> --apply  # 실제 저장
```

제목이 같은 문서가 있으면 교체하고 다시 임베딩한다. 아래 표는 스크립트의 `PLAN` 과 같은 값이다.

| 파일 | 문서 제목 | 공개 범위 |
|---|---|---|
| `01-site-guide-member.md` | 홈페이지 사용 안내 (부원) | **부원**(member) |
| `02-site-guide-staff.md` | 홈페이지 사용 안내 (운영진) | **운영진**(staff) |
| `03-site-guide-board.md` | 홈페이지 사용 안내 (회장단) | **회장단**(board) |

공개 범위를 셋으로 나눈 이유: 부원에게 예약 큐 설명이 검색되면 있지도 않은 화면을 안내하게 된다.
`search.ts` 의 visibility 필터가 질문자 역할 이하 문서만 집어 오므로, **역할별로 다른 답**이 나간다.

## 고칠 때 지킬 것

- **날짜를 적지 않는다.** 총회·MT 같은 것은 `/calendar` 에 넣는다(결정 86). 문서에 적으면 낡는다.
- **개인정보를 적지 않는다.** 명단·연락처·계좌·이메일 주소는 저장 단계에서 걸린다(`rag/pii.ts`).
- **화면에 실제로 적힌 문구 그대로** 버튼·메뉴 이름을 쓴다.
- 한 문장 = 한 동작. 전문용어를 쓰지 않는다("임베딩" → "챗봇이 읽는 자료").
- `##` 단위로 청킹되므로 **한 절에 한 주제**만 담는다. 한 절이 1,250자를 넘으면 잘린다.
- 화면을 고쳤으면 이 파일도 고치고 **다시 올린다**(`/documents` 붙여넣기 또는 위 스크립트).
  저장할 때만 반영된다 — 파일을 고쳐 커밋하는 것만으로는 챗봇이 달라지지 않는다.

## 화면 도움말과의 관계

화면 안 `도움말` 팝업 원문은 `src/guides/content.ts` 이고 이 폴더와 별개다.
도움말은 **그 화면을 보고 있는 사람**에게, 이 문서는 **챗봇에게 물어본 사람**에게 답한다.
겹치는 내용이 있는 것은 의도된 것이지만, 한쪽을 고치면 다른 쪽도 볼 것.
