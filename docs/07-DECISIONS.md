## 2026-07-24 보안 QA — 악의적 사용자 전제 점검
9. **계정 열거 차단 — 구분 정보를 메일함으로 옮긴다**: 가입 요청(`/api/auth/signup/request`) 응답은
   가입 여부와 무관하게 항상 동일하다(기존 409 `already_registered` 제거). 이미 가입된 주소에는
   인증 코드 대신 **"이미 가입된 계정입니다" 안내 메일**을 보낸다.
   → 구분 정보가 HTTP 응답이 아니라 **본인만 볼 수 있는 채널**로만 가므로 UX 손실 없이 열거만 막힌다.
   같은 이유로 OTP 재전송 쿨다운(429)도 삼킨다 — "가입된 주소만 429" 가 되면 그 자체가 오라클이다
   (로그인 경로에도 같은 구멍이 있어 함께 수정). 주소 단위 발송 상한(`mail_to_address`, 5회/시간)으로
   응답 통일 후 생기는 메일 폭탄 경로를 막는다.
10. **CSP `unsafe-inline` 제거는 챗봇(1D) 착수 시점에**: 지금은 앱에 HTML 주입 지점이 0건이고
   (`dangerouslySetInnerHTML` 미사용, React 가 전부 이스케이프) nonce 도입에 미들웨어가 필요해
   비용 대비 실익이 없다. **LLM 응답을 렌더링하는 챗봇이 전제를 바꾸므로** 1D 첫 작업으로 넣는다
   (1D 항목 + DoD 에 명시). 그때까지는 `frame-ancestors 'none'` 등 나머지 지시문이 방어를 담당한다.
11. **세션 무효화 = `users.session_version`**(0010). 별도 세션 테이블을 만들지 않는다.
   JWT 에 발급 시점 세대(`sv`)를 담고 요청마다 DB 값과 대조해 불일치면 401. 값을 1 올리면
   그 계정의 모든 기기가 즉시 로그아웃된다. 권한을 어차피 매 요청 DB 에서 읽으므로(`loadActor`)
   같은 SELECT 에 컬럼 하나를 얹는 것이라 **추가 조회 비용이 없다**. 회원 관리 화면에
   "모든 기기에서 로그아웃" 버튼으로 노출(2회 클릭 확인). sysadmin 대상은 sysadmin 만 가능.
   ※ 이 컬럼은 원래 설계에 없던 것을 이번에 신설한 것이다(0010).
12. **회장단 상호 신뢰 유지 + 안전장치 2개**: sysadmin 만 회장단을 강등하게 만들면 개발자가 졸업 후
   거버넌스의 단일 병목이 된다. 회장단 교체·유고 대응은 회장단이 스스로 할 수 있어야 하므로
   **상호 견제는 코드 차단이 아니라 가시성으로 푼다**.
   (a) **마지막 활성 권한자(회장단·시스템관리자) 1인은 강등·비활성화 불가**(`last_privileged`)
       — 전원 잠금 시 부트스트랩 스크립트 없이는 복구가 불가능하다.
   (b) 회장단 대상 권한 변경·강제 로그아웃은 **audit 에 `[high]` 표기 + 회장단 전원과 공용 메일로 즉시 알림**.
       행위자 본인도 수신자에 포함한다 — 계정 탈취 시 "내가 하지 않은 알림"이 가장 빠른 탐지 신호다.

13. **비활성화·강등 시 세션도 함께 끊는다**(`session_version` + 1): 비활성화의 의도는
   "이 사람의 접근을 **지금** 끊는다" 인데, 세션을 남겨 두면 쓰기만 막히고 화면 열람은 계속돼
   의도와 어긋난다. 운영진을 퇴출하거나 계정 이상이 의심되는 상황에서는 **읽기 접근 자체가 리스크**다.
   강등(회장단→운영진→부원)도 같다 — 역할이 줄었는데 이전 역할로 발급된 토큰이 살아 있을 이유가 없다.
   - 적용: `setMemberActive(false)`, `setMemberRole`(강등일 때만). **재활성화·승격은 올리지 않는다**
     (끊을 이유가 없고, 로그인 중 승격된 사람을 튕겨낼 필요도 없다).
   - 강등 판정은 `isDemotion()` 순수 함수. `board`↔`sysadmin` 은 등급이 같지만 **sysadmin → 그 외**는
     sysadmin 전용 조작을 잃으므로 축소로 본다.
   - audit 의 `after.sessionsRevoked` 로 "이 변경이 세션을 끊었는지" 를 남긴다.
   - 참고: 인가는 원래 매 요청 DB 에서 역할을 다시 읽으므로(`loadActor`) **강등 후 권한이 남는
     구멍은 없었다**. 이 결정은 그 위에 얹는 방어이자 제품 동작의 일관성 확보다.

## 2026-07-24 챗봇(1D) 착수 — 모델 ID 확정
14. **Gemini 모델 ID 는 실측으로 확정하고 env 로만 주입한다**(코드 기본값 금지).
   확인 도구: `node scripts/list-gemini-models.mjs [--probe]` — 지금 키로 실제 호출 가능한 모델과
   임베딩 출력 차원을 찍어 본다. 제품명과 API ID 는 다르고, 목록은 시간이 지나면 변한다.
   - **생성: `gemini-3.1-flash-lite`** (확정). 근거 = **단가**: $0.25/$1.50(입력/출력, 100만 토큰당)로
     `gemini-3.5-flash-lite`($0.30/$2.50)보다 싸다. RAG 는 검색된 근거로 답하는 일이라 3.5 의
     에이전틱 강화가 필요 없어, 더 비싼 모델을 쓸 이유가 없다.
     - 후보 `gemini-3.5-flash-lite`: **단가 역전 또는 3.1 의 품질 이슈가 확인되면 재검토**한다.
       env 로만 주입하므로 교체는 값 하나 바꾸는 일이다(생성 모델은 저장 데이터와 무관해 언제든 교체 가능).
     - `gemini-2.5-flash-lite` 는 구세대라 제외.
   - **임베딩: `gemini-embedding-2`** (`-preview` 아닌 안정판.)
   - **`-latest` / `-preview` 접미사 ID 는 쓰지 않는다**: 내용이 예고 없이 바뀌면 핀 고정이 무의미해지고,
     임베딩이 바뀌면 이미 저장한 벡터와 의미 공간이 어긋나 검색 품질이 조용히 망가진다.

15. **임베딩 차원은 768 을 유지한다 — `outputDimensionality=768` 로 요청**(마이그레이션 없음).
   `gemini-embedding-2` 의 기본 출력은 **3072차원**이라 `doc_chunks.embedding = vector(768)` 과 맞지 않는다.
   세 가지 길을 재 보고 768 로 결정했다:
   - ❌ 컬럼을 `vector(3072)` 로 확대: **불가**. 이 DB(pgvector 0.8.2)에서 실측 결과
     `column cannot have more than 2000 dimensions for hnsw index` — 인덱스를 못 만들면
     문서가 늘수록 전체 스캔이라 검색이 무너진다.
   - △ `halfvec(3072)`로 우회: HNSW 한도는 넘기지만 정밀도를 깎고 스키마·쿼리가 복잡해진다.
     300명 규모 문서량에 치를 비용이 아니다.
   - ✅ **`outputDimensionality=768`**: Gemini 임베딩은 Matryoshka 축소를 지원한다.
     실측으로 768차원이 나오고 **L2 노름이 1.0 으로 이미 정규화**돼 있어(코사인 검색 전제 충족)
     추가 정규화도 필요 없다. 기존 스키마·HNSW 인덱스를 그대로 쓴다.
   → **호출부는 `outputDimensionality` 를 반드시 명시해야 한다.** 빠뜨리면 3072차원이 돌아와
     삽입이 실패한다(차원 불일치). 이 값은 `doc_chunks.embedding` 정의와 한 몸이므로,
     차원을 바꾸려면 컬럼 재생성 + **전 문서 재임베딩**이 함께 가야 한다.

## 2026-07-24 챗봇(1D) — 1D-1: nonce 기반 CSP (결정 10 이행)
16. **CSP nonce 는 미들웨어에서, unsafe-inline 은 script-src 에서 제거**(`src/middleware.ts`).
   요청마다 nonce 를 발급해 `script-src 'self' 'nonce-…' 'strict-dynamic'` 로 내보낸다.
   Next 가 이 nonce 를 자기 스크립트에 붙이고, nonce 없는 스크립트(주입된 XSS)는 브라우저가 거부한다.
   정적 헤더(XFO·nosniff·HSTS 등)는 nonce 와 무관하므로 `next.config.mjs` 에 그대로 둔다.
   - **정적 프리렌더 페이지는 동적으로 전환해야 한다**: nonce 는 매 요청 바뀌는데 정적 페이지는
     빌드 시점 nonce 가 박혀 응답 헤더와 어긋난다 → 스크립트 전부 차단 = 화면 깨짐.
     `login`/`signup` 을 `page.tsx`(서버, `force-dynamic`) + `form.tsx`(클라이언트)로 쪼갰다.
     나머지 화면은 이미 전부 동적(인증 게이트)이라 그대로 동작한다.
   - **남는 한계(의도적)**:
     · `style-src` 는 `'unsafe-inline'` 을 **유지**한다 — React 인라인 style 속성과 Next/styled-jsx 의
       `<style>` 때문이며, 스타일 주입은 스크립트 주입과 달리 위험도가 낮다(코드 실행 불가).
       챗봇이 다루는 위험은 스크립트 실행이고 그건 막았다. DoD 의 "unsafe-inline 없음" 은 script-src 기준.
     · 기본 404 는 정적이라 프레임워크 스크립트가 차단될 수 있어 `not-found.tsx` 를 **JS 없이도 동작하는
       순수 HTML(+홈 링크)** 로 만들었다. 내용·링크는 정상, 콘솔 잡음만 남는다(에러 페이지라 무해).
   - 검증: `/login`·`/signup` 의 응답 CSP nonce 와 HTML 의 모든 `<script nonce>` 가 일치, nonce 없는
     인라인 스크립트 0개, script-src 에 unsafe-inline 없음(2026-07-24 prod 빌드 실측).

   회원·지원자 전원의 개인정보가 이미 남의 손에 복사돼 있다"는 뜻이기도 하다. 유출 사고의
   피해 범위를 열쇠 관리 하나에 전부 거는 설계는 받아들이지 않는다.
   - Supabase 비공개 버킷도 탈락시켰다. **백업 대상과 같은 프로젝트 안**이라 오프사이트가 아니다
     (프로젝트 정지·삭제·계정 탈취 시 원본과 백업이 함께 사라진다). 무료 티어 1GB 도 같이 쓴다.
   - 채택: GitHub Org 소유의 **별도 private 리포** `animalmate-backups`. 접근은 fine-grained PAT
     하나로, 대상 리포 1개 + Contents write 로만 제한한다. 광범위 토큰을 쓰면 백업 잡이
     리포 전체를 만질 수 있는 열쇠가 되어 백업이 오히려 공격 표면이 된다.
   - 부수 결정: 암호화는 `age` 대신 **GPG 대칭**을 쓴다. `age` 는 암호(passphrase) 모드가 TTY 를
     요구해 CI 에서 비대화식으로 돌지 않는다. 파일 확장자도 `.age` 가 아니라 `.gpg` 로 둔다 —
     형식과 다른 확장자를 붙이면 복원하는 사람이 잘못된 도구를 먼저 집는다.

46. **챗봇 출처는 모델이 아니라 검색 메타데이터가 표시한다.**
   CLAUDE.md 필수원칙 #7 은 "답변에 출처 문서명을 표시한다"였는데, 실제 시스템 프롬프트에는

   발견). 어느 쪽이 옳은지가 아니라 **누가 표시하느냐**가 문제였다.
   → 모델에게 출처를 쓰게 하면 ① 문장 사이에 "(출처: …)"가 끼어 답변이 읽기 나빠지고
   ② 무엇보다 **없는 문서명을 지어낼 수 있다**. 출처는 "모델이 무엇을 봤다고 말하는가"가 아니라
   "검색이 실제로 무엇을 집어 왔는가"여야 한다. 후자는 지어낼 수 없는 값이다.
   - 시스템 프롬프트는 **그대로 둔다**(본문에 출처 금지).
   - 표시는 UI 가 한다 — `/api/chatbot/ask` 가 이미 돌려주고 `chat_logs.sources` 에 남기던
     검색 메타데이터로 답변 아래에 칩을 그린다.
   - 근거를 못 찾아 핸드오프한 답변에는 칩을 붙이지 않는다. 붙이면 "자료를 보고 모른다고 한 것"
     처럼 읽혀서 사실과 어긋난다.
   - CLAUDE.md #7 을 이 방식으로 개정했다.

47. **문서가 있다고 말하는 기능은 코드로 만들거나 문서를 고친다 — 둘 중 하나만 한다.**
   현황 점검에서 **임기 자동 만료 크론이 아예 없다**는 것이 드러났다. CLAUDE.md 필수원칙 #2,

   사람이 비활성화해 줄 때까지 남아 있었다 — **문서만 읽으면 안전하다고 착각하게 되는 상태**다.

     롤백한다. 이 제약을 테스트 파일 맨 위에 적어 두었다.

48. **개인정보처리방침은 화면이 아니라 코드 한 곳에서 나온다.**

     적으면 방침이 아니라 장식이다. 스키마를 바꾸면 같은 커밋에서 이 파일도 고친다.
   - 동의는 체크박스로 받고 **서버에서 다시 검사한다**(규칙 #6). 화면에서 버튼을 잠그는 것은

   - 챗봇 질문이 Google(Gemini)로 전송된다는 사실을 위탁 항목에 명시했다. 이건 이용자가
     알아야 하는 사실이지 숨길 구현 세부가 아니다.

49. **양식은 "쓰는 범위"와 "고치는 범위"를 따로 둔다.**
   예약을 만들 때 불러올 수 있는 양식이 **소속 팀 것으로 좁혀져** 있었다. 그런데 예약을 만드는 것은
   양식을 **베껴 쓰는** 일이다 — 제목·본문·기본값을 복사해 갈 뿐, 그 양식도 그 팀도 바뀌지 않는다.
   좁혀 둘 이유가 없었고, 오히려 `team_members` 배정이 비어 있는 운영진은 global 밖에 못 써서
   매번 처음부터 쓰고 있었다.
   → **쓰는 범위 = 개인 소유(남의 것)를 뺀 전부**(global + 모든 팀 + 본인 개인). 역할과 무관하다.
   - **고치는 범위는 그대로다** — 수정·삭제는 소유자(본인/소속팀) + 회장단(`template.manage`).
     넓힌 것은 쓰기뿐이다. 통합 테스트가 "목록에는 있는데 수정은 막힌다"를 못박는다.
   - 남의 **개인** 양식만 뺀다. 개인 소유는 각자의 초안이라 남에게 제안할 것이 아니다.
     (예전에는 회장단·시스템관리자에게 남의 개인 양식까지 보였다. 그 부분은 오히려 좁아졌다.)
   - 목록이 넓어지면 관리 화면에 **고칠 수 없는 양식에도 수정 버튼**이 뜬다 → 누르면 403.
     서버가 양식마다 `canEdit` 을 계산해 내려주고 화면은 그것만 본다. 판정을 화면에 다시 구현하지
     않는다 — 규칙을 두 벌 두면 갈라지고, 갈라지면 "버튼은 있는데 안 되는" 화면이 된다.
     `canEditTemplate` 은 `authorizeTemplate` 을 그대로 호출한다(구조적으로 갈라질 수 없게).
   - 버튼을 지우는 대신 왜 못 고치는지를 적는다("다른 팀(읽기)"). 버튼만 없으면 고장으로 보인다.

50. **함수는 서울에서 돈다 — DB 옆에.** (2026-07-29)
   "사이트가 좀 느리다"의 대부분은 코드가 아니라 **지리**였다. 응답 헤더가 그대로 말해 준다:
   `X-Vercel-Id: icn1::iad1` — 요청은 서울 엣지(icn1)로 들어오는데 **함수는 버지니아(iad1)에서
   실행**됐고, Supabase 는 서울(`ap-northeast-2`)이다. 그래서 쿼리 한 번마다 태평양을 왕복했다.
   - 측정: `/login`(DB 조회 없음) TTFB ≈ 350ms, `/api/health`(`select 1` 한 번) ≈ 530ms.
     차이 ≈ **180ms 가 DB 왕복 1회의 값**이었다.
   - → `vercel.json` 에 `"regions": ["icn1"]`. 왕복이 같은 리전 안에서 끝난다.
   - **`vercel.json` 에 `crons` 를 넣지 말 것**(규칙 #7). 이 파일이 생겼다고 해서 Vercel Cron 을
     쓸 수 있게 된 것이 아니다 — 스케줄은 계속 pg_cron 이다. 이 파일의 용도는 리전 고정뿐이다.

51. **로그인한 모든 요청이 지나는 길목은 왕복 1번이어야 한다.** (2026-07-29)
   `loadActor` 가 users → memberships → team_members 를 **순차로** await 했다. 서로 필요로 하지
   않는데도 줄을 섰다. 이 함수는 페이지 HTML 과 그 화면이 부르는 API **양쪽 모두**가 통과하므로,
   화면 하나를 보는 데 왕복 6번(결정 50 기준 ≈ 1초)이 붙었다.
   → `Promise.all` 로 묶어 요청당 3왕복 → 1왕복.
   - users 가 없거나 거부될 때 나머지 둘이 헛돈다. 비정상 경로이고 둘 다 인덱스 한 방이라 싸다 —
     정상 경로에서 2왕복을 없애는 쪽이 훨씬 크다.
   - 같은 조회에 `users.name` 을 얹어 `Actor.name` 으로 내린다. 홈 화면이 인사말 하나 때문에
     users 를 **또** 조회하던 것을 없앴다. 단, **권한 판단에는 절대 쓰지 않는다** — 그래서
     optional 이다(권한만 보는 호출부는 채우지 않아도 된다).

52. **렌더를 막는 것은 CSS 파일 안에 숨어 있었다.** (2026-07-29)
   `globals.css` 첫 줄의 `@import url(jsdelivr…pretendard…)` 는 빌드 후에도 그대로 남아,
   브라우저를 **한 줄로 세웠다**: HTML → 앱 CSS 받고 파싱 → 그제야 jsdelivr 발견 → 새 커넥션
   (DNS+TCP+TLS) → 53KB CSS → woff2. 셋 다 렌더 차단이라 그동안 화면이 비어 있다.
   → `layout.tsx` 의 `<link rel="stylesheet">` 로 옮기고 `<link rel="preconnect">` 를 앞세웠다.
   HTML 파싱 즉시 발견되어 앱 CSS 와 **동시에** 받는다.
   - `preconnect` 에 `crossOrigin` 이 있어야 한다. 폰트는 익명 CORS 요청이라, 없으면 커넥션이
     재사용되지 않고 두 번 열린다.
   - dynamic-subset(@font-face 92개, unicode-range 분할)은 그대로 둔다. 한글 전체를 담은 단일
     variable 파일은 1MB 가 넘는데, 이건 화면에 실제로 쓰인 글자 조각만 받는다.

55. **Supabase 경고를 따라 pgvector 를 `public` → `extensions` 로 옮겼다.** (2026-07-29)
   Security Advisor 의 `extension_in_public`(WARN). **RLS 경고가 아니었다** — 받은 메일을 "RLS 가
   꺼졌다"로 읽고 조사에 들어갔지만, 조회해 보니 운영·테스트 양쪽 다 public 전 테이블 RLS 가
   켜져 있었다(운영 29/29, 테스트 27/27, `test:rls:prod` 88 통과). 경고의 실체는 확장 위치였다.
   - **보안 위험 자체는 이 프로젝트에 없었다.** 이 린트가 경고하는 공격은 "신뢰할 수 없는 롤이
     `public` 에 같은 이름의 함수를 만들어 search_path 로 확장 함수를 가로채는 것"인데,
     `anon`·`authenticated`·`PUBLIC` 모두 public 에 **CREATE 권한이 없다**(USAGE 만).
   - **그런데도 지금 한 이유는 비용이다.** `doc_chunks` 가 운영 2행/테스트 0행으로 사실상 비어
     있었다. 다음 할 일이 "챗봇 핵심 문서 5개 입력"이라 이 표는 곧 커진다 — 나중에 하면 같은
     작업이 무거워진다. 경고를 무시할지 말지가 아니라, **언제 하면 제일 싼가**의 문제였다.
   - 안전 근거: `vector` v0.8.2 는 `extrelocatable=true`. 운영·테스트 모두 앱이 `postgres` 롤로
     붙고 search_path 가 이미 `extensions` 를 포함해, `src/rag/search.ts` 의 미자격 `::vector`·`<=>`
     와 `schema.ts` 의 `vector_cosine_ops` 가 그대로 해석된다. 컬럼 타입과 HNSW 인덱스는 OID 로
     묶여 있어 재생성이 필요 없다(이전 후 인덱스 정의 동일 확인).

56. **`anon`/`authenticated` 의 public 권한을 회수해 방어선을 두 겹으로 만들었다.** (2026-07-29, 0022)
   운영 DB 에만 anon·authenticated 에 public 전 테이블 ALL PRIVILEGES 가 부여돼 있었다
   (27테이블 × 2롤, INSERT·DELETE·TRUNCATE 까지). Supabase 구버전 프로젝트의 기본값이다.
   테스트 DB(신규 생성)는 0건이었다.
   - **증상이 말해 주던 것**: 회수 전 anon SELECT 는 `HTTP 200 []` 를 반환했다. 200 은 요청이
     **테이블까지 도달했고 RLS 가 마지막에 걸러냈다**는 뜻이다. 회수 후에는 `401 / 42501
     (insufficient_privilege)` — 권한 계층에서 먼저 막힌다. 실피해는 없었지만 안전망이 한 겹뿐이었다.
   - **왜 위험한가**: 새 테이블에 `ENABLE ROW LEVEL SECURITY` 를 한 줄 빠뜨리면(= `db:generate` 가
     만들어 주지 않아 매번 손으로 넣어야 하는 그 구문) 그 테이블은 즉시 anon key 로 읽기·쓰기까지
     뚫렸다. 2026-07-27 사고가 정확히 그 형태였다. 이제는 RLS 를 빠뜨려도 권한이 없어 막힌다.
   - **기존 부여 회수만으로는 반쪽이었다.** public 스키마에 `ALTER DEFAULT PRIVILEGES` 가 걸려 있어
     **앞으로 만드는 테이블이 다시 자동으로 권한을 받는다.** 그것까지 끊어야 한다 — 이게 이
     마이그레이션의 핵심이고, 테스트 DB 에 기본권한이 애초에 없어서 부여도 0건이었던 이유다.
   - **`service_role` 은 남겼다.** 서버 전용 키(`src/storage/notice-images.ts` 가 Storage REST 에 쓴다)라
     유출되면 어차피 RLS 를 우회한다 — 회수해도 공격면이 줄지 않는다. 공개되는 것은 anon key 이고,
     `authenticated` 는 그 anon key 로 Supabase Auth 가입을 하면 얻을 수 있어 실제 표적은 이 둘이다.
   - **남은 구멍 하나(의도적)**: `by=supabase_admin` 기본권한은 그대로다. `postgres` 가 그 롤의
     멤버가 아니라 손댈 수 없다(마이그레이션에서 시도 → `insufficient_privilege`, 예외로 넘김).
     supabase_admin 이 public 에 테이블을 만들 때만 해당되는데 이 리포는 그런 일을 하지 않는다.
     드리즐 마이그레이션도 대시보드 SQL 에디터도 `postgres` 로 돈다.
   - **테스트 단언문은 고칠 필요가 없었다.** `test/rls.security.test.ts` 는 이미 4xx 를 "접근 거부 =
     안전"으로 처리한다(위험한 것은 200 + 행 반환뿐). 착수 전에 파일을 읽고 확인했다.
   - 검증: 테스트 DB 적용 후 통합 141 통과(동일), 운영 적용 후 anon 401 확인, RLS 82 통과,
     배포본 e2e 10 통과.

57. **CI 가 챗봇·pgvector 테스트 9개를 한 번도 돌린 적이 없었다(가짜 초록).** (2026-07-29)
